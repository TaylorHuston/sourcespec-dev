# Todo example

A small Vite + React + TypeScript app for trying SourceSpec against real functions and UI events. Create a local account or sign in, then add, complete, or remove your own tasks. Users, sessions, and tasks live in an ignored SQLite file at `.data/todos.sqlite` and survive dev-server restarts. There is no external service or browser storage.

`openapi.yaml` at the app root is the canonical HTTP contract for `/api/auth` and `/api/todos` (operations, inputs, outputs, and error responses). `npm test` validates the HTTP contract, checks that behavior-case and operation links resolve to the function and test catalogs, and runs the Requirement checks described below. `.sourcespec/catalogs/functions-catalog.yaml` inventories **every app-owned function definition**, including anonymous callbacks in runtime, config, and test files. It is generated by `../../tools/function-catalog.mjs`. Function `location` is a file path, not a line number; anonymous entries use `name: null` and a searchable `context`. `sourceScope` classifies the owning file as application, test, tooling, or unclassified; functions inside tests are not necessarily test declarations. The generator preserves existing IDs and prose when it can match a function without ambiguity, and gives new functions opaque UUID-based IDs. Older position-shaped IDs remain unchanged to preserve links, but source offsets are no longer stored or used after migration. Moves, renames, and ambiguous callback changes require human reconciliation. `return.type` is a concise call return type (for example `Todo | null`, `Promise<Todo>`, or `object` for an anonymous structural object), not a fully expanded inferred type; declared/curated named types remain meaningful. `.sourcespec/catalogs/tests-catalog.yaml` is still hand-authored and records component, API, and contract tests. `.sourcespec/behaviors/` has separate records for creating an account, signing in, signing out, adding a task, changing completion, and removing a task, using `../../schema/behaviors.yaml`. Each case states its condition and intended outcomes, with curated function pointers for debugging and tests intended to check it. Those links are neither an ordered/exhaustive call trace nor evidence of a passing test run.

The parallel `.sourcespec/requirements/` experiment uses `../../schema/requirements.yaml`: one current-state SHALL obligation per kebab-case file, with distinct named GIVEN/WHEN/THEN Scenarios expressed as nonempty lists. `implementedBy` and `verifiedBy` are optional curated pointers, not proof that code implements the prose or that a test passes. Stories under `docs/stories/` can group and share Requirements; planned work belongs outside `.sourcespec/`. Run `npm run requirements:check` to validate the JSON Schema, filename/ID and per-Requirement Scenario ID uniqueness, function/test catalog references, and that each referenced catalog test's named declaration is present in its source file. Test discovery is not semantic coverage or a test result. Both `npm test` and `npm run build` run this check.

Keep one behavior per file under `.sourcespec/behaviors/`, scoped to one trigger and its meaningful cases. `.sourcespec/operations/local-http.yaml` links each of OpenAPI's eight `operationId`s to a shared Vite middleware mount, a curated handler function, and intended tests, following `../../schema/operations.yaml`. The operation map does not repeat HTTP methods, request/response shapes, or behavior outcomes, and its link check does not prove that the dev or preview server actually routes a request. `.sourcespec/data-models/local-todo.yaml` is a SourceSpec YAML map of the users, todos, and sessions tables and their foreign-key relationships, validated against actual SQLite metadata; it points to DDL and API/code representations instead of duplicating columns. Its shape is defined by `../../schema/data-models.yaml`. Cases do not prescribe a sequence, and HTTP payload/response contracts belong in OpenAPI. YAML filenames use kebab-case. An index can be generated later.

Requires Node.js 26+ for the built-in `node:sqlite` module. Vite hosts the local APIs at `/api/auth` and `/api/todos` during development and preview; it creates the ignored database file automatically. Register a username (3–32 characters, starting with a letter) and password (8–128 characters). Passwords are salted and hashed with scrypt; opaque session tokens are stored hashed in SQLite and sent via HTTP-only, SameSite=Strict cookies lasting seven days. Task operations check the session and owner on the server. An existing single-user database is migrated without dropping rows: the first locally registered account claims legacy tasks. This loopback-only experiment lacks account recovery, rate limiting, and production hardening; do not expose it publicly or reuse passwords from real accounts.

```bash
npm install
npm run dev
```

Open the local URL printed by Vite. Run `npm test` for component, API, and contract tests, `npm run build` to type-check and build, or `npm run preview` after building to serve the build with the same local API. Both tests and builds run `npm run catalog:check` and `npm run requirements:check`; after changing app code, run `npm run catalog:refresh` and review any ID changes before verifying. Stop the server before removing `.data/todos.sqlite` if you intentionally want to reset your local tasks.
