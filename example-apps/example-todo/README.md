# Todo example

A small Vite + React + TypeScript app for trying SourceSpec against real functions and UI events. Create a local account or sign in, then add, complete, or remove your own tasks. Users, sessions, and tasks live in an ignored SQLite file at `.data/todos.sqlite` and survive dev-server restarts. There is no external service or browser storage.

`openapi.yaml` at the app root is the canonical HTTP contract for `/api/auth` and `/api/todos` (operations, inputs, outputs, and error responses). `npm test` validates the HTTP contract, checks operation and Requirement links against the function and test catalogs, and runs the Requirement checks described below. `.sourcespec/catalogs/functions-catalog.yaml` inventories **every app-owned function definition**, including anonymous callbacks in runtime, config, and test files. It is generated and checked by the standalone SourceSpec CLI at `../../cli/` (also usable manually from `~/.sourcespec/bin/sourcespec`). IDs spell out the owning file and lexical chain, e.g. `fn:src/App.tsx#App.addTodo`; only collisions or context-free anonymous functions use an explicit UTF-16 range suffix. Function `location` is a file path, not a line number; anonymous entries use `name: null` and a searchable `context`. `sourceScope` classifies the owning file as application, test, tooling, or unclassified; functions inside tests are not necessarily test declarations. The generator preserves reviewed annotations when identities match and gives new functions readable IDs. Moves, renames, a new collision, and ambiguous callback changes require human reconciliation of authored links. `return.type` is a concise call return type (for example `Todo | null`, `Promise<Todo>`, or `object` for an anonymous structural object), not a fully expanded inferred type; declared/curated named types remain meaningful. `.sourcespec/catalogs/tests-catalog.yaml` uses readable `test:<file>#<suite.test-title>` IDs for static test declarations, with reviewed descriptions and kinds for component, API, integration, and contract tests. `.sourcespec/requirements/` is the chosen current-state behavior format. It uses the shared `~/.sourcespec/schema/requirements.yaml` (installed from `../../schema/requirements.yaml`): one current-state SHALL obligation per kebab-case file, with distinct named GIVEN/WHEN/THEN Scenarios expressed as nonempty lists. `implementedBy` and `verifiedBy` are optional curated pointers, not proof that code implements the prose or that a test passes. Stories under `docs/stories/` can group and share Requirements; planned work belongs outside `.sourcespec/`. Run `npm run requirements:check` to validate against the shared JSON Schema, filename/ID and per-Requirement Scenario ID uniqueness, and function/test catalog references. Run `npm run tests-catalog:check` to validate static JS/TS test declarations (including suites) and lexical IDs. Test discovery is not semantic coverage or a test result. Both `npm test` and `npm run build` run this check.

Keep one Requirement per file under `.sourcespec/requirements/`, with named Scenarios for its meaningful cases. `.sourcespec/operations/local-http.yaml` links each of OpenAPI's eight `operationId`s to a shared Vite middleware mount, a curated handler function, and intended tests, following the shared `~/.sourcespec/schema/operations.yaml` shape. The operation map does not repeat HTTP methods, request/response shapes, or behavior outcomes, and its link check does not prove that the dev or preview server actually routes a request. `.sourcespec/data-models/local-todo.yaml` is an authored map of table purposes, relationships, and API/code representations, validated against actual SQLite metadata. `.sourcespec/catalogs/data-model-catalog.yaml` is a generated physical inventory of the tables, columns, foreign keys, indexes, and DDL. The SQLite initializer in `server/todo-store.ts` remains authoritative. The installed `~/.sourcespec/schema/data-models.yaml` and `data-model-catalog.yaml` define the two record shapes. Cases do not prescribe a sequence, and HTTP payload/response contracts belong in OpenAPI. YAML filenames use kebab-case. An index can be generated later.

Requires Node.js 26+ for the built-in `node:sqlite` module. Vite hosts the local APIs at `/api/auth` and `/api/todos` during development and preview; it creates the ignored database file automatically. Register a username (3–32 characters, starting with a letter) and password (8–128 characters). Passwords are salted and hashed with scrypt; opaque session tokens are stored hashed in SQLite and sent via HTTP-only, SameSite=Strict cookies lasting seven days. Task operations check the session and owner on the server. An existing single-user database is migrated without dropping rows: the first locally registered account claims legacy tasks. This loopback-only experiment lacks account recovery, rate limiting, and production hardening; do not expose it publicly or reuse passwords from real accounts.

```bash
npm install
npm run dev
```

Open the local URL printed by Vite. Run `npm test` for component, API, and contract tests, `npm run build` to type-check and build, or `npm run preview` after building to serve the build with the same local API. From a fresh checkout, run `pnpm --dir ../../cli install --frozen-lockfile && node ../../cli/scripts/install-local.mjs` before testing this app. The CLI reads its installed shared schemas in `~/.sourcespec/schema/`; this app does not own schema copies. Both tests and builds run `npm run catalog:check`, `npm run tests-catalog:check`, `npm run data-model:check`, and `npm run requirements:check`; after changing app code, run `npm run catalog:refresh` and review any ID changes before verifying. For test-declaration changes, run `npm run tests-catalog:refresh` and review new IDs, descriptions, kinds, and all intended-check links. For DDL or migration changes, run `npm run data-model:probe`, `npm run data-model:refresh`, and `npm run data-model:check`, then review changes to the authored map. These scripts initialize and remove a schema-only database in a temporary directory; they do not inspect `.data/todos.sqlite` or store its rows. Stop the server before removing `.data/todos.sqlite` if you intentionally want to reset your local tasks.
